Set with the APB_BASE_URL environment variable. It is baked into every generated script, so changing it means regenerating them.

When an address gets blocked

the two settings that matter most

1 pushes an address the moment any router reports it.

Raising this to 2 requires a second site to agree before anything is blocked. Slower, and far less likely to block something by mistake.

An address not seen again for this long is released everywhere. 0 keeps it forever.

Defaults for new routers

RouterOS keeps entries with a timeout in RAM and never writes them to flash. 520w is about ten years and still displays correctly.

These apply to routers added from now on. Existing routers keep their own values, which you can change on each device page without regenerating anything.

Protocol limits

RouterOS truncates a fetch response well before 64 KB. 8192 is comfortable; raising it risks silent truncation on the router.

Matched against the X-Apb-Agent header the generated scripts send, or any User-Agent. RouterOS sets its own User-Agent and does not reliably let a script override it, which is why the dedicated header exists. Changing this stops every router that is already deployed: the value is baked into a bundle when it is generated, so you must then regenerate and reinstall every bundle. Until you do, those routers get the same 401 a bad token produces, and the server log names the expected and received values on every rejection. It only filters background internet noise before the token is checked and is not a substitute for the token, so leaving it empty is a reasonable choice.
